**What the platform is actually storing today**

| What you’ll see in the warehouse                   | Where it lives                        | Why it’s there                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------| ---------------------------------------| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Raw event stream (heartbeat / play / pause)**    | `session_state_rows` / `events_dedup` | The source of truth for every user action.  Stored once, never modified – used only for debugging or re‑ingest if a bug is discovered.                                                                                                                                                                                                                                       |
| **Normalized “active” session ranges**             | `session_active_intervals_clean`      | Every time a session ends—whether because the user stopped playing, paused for longer than the heartbeat timeout, or was truncated by a system rule—the pair `<interval_start , interval_end>` gets written here (one row per continuous active period).  It is the data‑model that feeds most **session‑level analytics**: total watch time, number of sessions, gaps, etc. |
| **Per‑minute concurrency deltas (pre‑aggregated)** | `concurrency_deltas`                  | As soon as a heartbeat or pause event arrives, the ingestion worker immediately emits a delta row (+1 for “start”, –1 for “stop”) into this table.  The table is built incrementally, so *every minute* the system knows the net change in active viewers.  This is the fast path for dashboards that show peak concurrency, hourly totals, and real‑time activity curves.   |
